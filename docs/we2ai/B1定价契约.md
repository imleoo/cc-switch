## 每个模型新增 `price`（对象，可省略）

与实际扣费**同源**：用网关计费的定价解析（分组价卡 → 渠道价 → catalog 自定义价 × discount_rate；复合分组按实际转发的目标模型解析）。

**v2 口径（服务端本轮实现中）**：`base_*` 是"标准首档价"，**已含**当前时刻的分时倍率与 DeepSeek 峰谷规则（这部分是渠道/供应商侧按时段浮动的标准报价，不是分组折扣，因此计入 `base_*` 本身），但**不含**长上下文分档、推理等级、服务档位倍率；折后价 = `base_* × 该模型 multiplier`（见下方 `multiplier` 字段行；token 类 `multiplier` = 分组倍率 `rate_multiplier` × 分组高峰 `peak_multiplier`，是"分组"这一层的折扣/加价，与 `base_*` 已经包含的"渠道分时定价"是两个不同层次，不会重复计入）。

**v6 口径（服务端实际服务范围收窄，历史记录，见下方 v7 更准确的完整条件列表）**：B1 这个接口目前只服务 Claude Code/Codex/WorkBuddy 三个**文本**工具的模型选择；图片/视频/音频等媒体类模型服务端**一律省略** `price`（客户端按既有规则显示"暂无定价"，不需要任何代码改动）。因此下表里 `billing_mode` 实际只会出现 `token` 与 `per_request`（文本类的按次计费）两种取值，且这两种取值下 `multiplier` 都等于分组倍率 `rate_multiplier` × 分组高峰 `peak_multiplier`（与顶层 `pricing.effective_multiplier` 一致）；`billing_mode` 为 `image`/`video`/`audio` 等媒体类值，以及"模型自己的 `multiplier` 独立于顶层、不叠加分组高峰"这种情形，都是为可能的未来范围扩展保留的类型定义与客户端兼容能力，当前不会出现在真实数据里。

**v7 口径（服务端再次收窄，取代 v6 "仅媒体类模型省略 `price`" 的表述）**：服务端只有在能**静态确定**计费模型就是这个模型本身时才返回 `price`；下列任一条件命中都会让服务端整体省略这个模型的 `price`：
1. 渠道模型映射（渠道侧把实际计费模型映射成了别的模型）；
2. `billing_model_source = response_model`（计费模型要从响应里的模型名才能确定，请求时刻无法静态推断）；
3. OpenAI 家族 messages dispatch 映射（请求被转发调度到另一个模型）；
4. 账号模型映射，且候选账号里任一个会把模型名改掉（不是"取第一个能确定的候选账号"，只要存在任一个会改名的候选账号就整体省略；**账号恒等映射 A → A 不算改名，不触发这条**）；
5. 复合分组的公开别名本身已经带有显式价（不需要再解析到实际转发的目标模型价格）；
6. 媒体类模型（v6 已记录的情形，仍然成立）；
7. 无法解析出价格；
8. 复合分组公开别名 P 与目标 U 不同，且渠道 `billing_model_source = requested`；
9. OpenAI 家族分组中，模型名推理后缀归一化结果 ≠ 自身即省略（如 `gpt-5.4-xhigh` → `gpt-5.4`；与账号映射无关，即使账号对两个名字都配了恒等映射也省略）；
10. 国产供应商等账号的真实计费候选过滤会把该模型剔除（如 Kimi 分组下没有显式价的 Claude 模型，实际按零成本记账）；
11. 没有候选账号；
12. 原生（Anthropic 等非 OpenAI 路由）messages 请求解析会剥除 `[1m]` 等后缀，归一化结果 ≠ 自身即省略（如 `claude-sonnet-4-5[1m]`）。

比 v6 的表述更准确：不是"只有媒体类模型会被省略"，而是"计费模型在请求时刻无法静态确定的所有情形都会被省略"，媒体类模型只是其中一种。**有 `price` 时**，`multiplier` 恒等于分组倍率 `rate_multiplier` × 分组高峰 `peak_multiplier`（与顶层 `pricing.effective_multiplier` 相同）——因为会导致"模型自己的倍率独立于顶层"的所有情形本身就在上面的省略条件列表里，服务端只要返回了 `price` 就不可能出现独立倍率。

| 字段 | 类型 | 含义 |
|---|---|---|
| `billing_mode` | string | 当前实际只会是 `token` 或 `per_request`（v7：任何计费模型无法静态确定为模型本身的情形——含媒体类模型——服务端整体省略 `price`，见上）；类型定义仍保留 `image`/`video`/`audio` 等其他后端枚举值，供未来范围扩展 |
| `input` `output` `cache_read` `cache_write` `cache_write_1h` | number? | **已乘该模型 `multiplier`**（见下）的美元单价，token 类为每 1M tokens；无数据省略 |
| `per_request` | number? | 按次计费的美元单价（已乘该模型 `multiplier`） |
| `base_input` `base_output` `base_cache_read` `base_cache_write` `base_cache_write_1h` `base_per_request` | number? | 未乘 `multiplier` 的标准首档价（已含渠道分时/峰谷定价，见上；用于划线原价） |
| `multiplier` | number（v2 新增，**本轮起服务端总是输出**） | 该模型**实际扣费倍率**：v7 范围下——只要服务端返回了 `price`（见上方 v7 的省略条件列表）——恒等于分组倍率 `rate_multiplier` × 分组高峰 `peak_multiplier`，与顶层 `effective_multiplier` 一致；类型定义仍保留"模型有独立倍率、不叠加分组高峰"这种可能性（供未来范围扩展，当前不会出现）。客户端仍按 `Option` 处理（兼容尚未升级到 v2/v3 的旧服务端），缺失或无效时回退到顶层 `pricing.effective_multiplier` |
| `per_request_unit` | string?（v3 新增） | 按次计费的单位：`"request"` 或 `"second"`。**v7 范围下服务端只会输出 `"request"`**（`"second"` 是为按秒计费的媒体类模型——如视频——保留的类型定义；v7 收窄后媒体类模型连 `price` 都会被整体省略，所以当前范围内不会出现；客户端对 `"second"` 的识别与展示逻辑作为前向兼容保留，不删除）。客户端在 Rust 侧的 wire 类型是 `Option<Option<String>>`（Codex 复验 C4），区分"字段完全不存在"（外层 `None`）与"字段存在但显式给了 `null`"（外层 `Some`、内层 `None`）——单层 `Option<String>` 反序列化时 serde 会把这两种情形都折叠成同一个 `None`，导致显式 `null` 被误当成缺省。归一化规则：**字段完全不存在**（`omitempty`）时按 `"request"` 处理；显式给出的值只要不是 `"request"` 也不是 `"second"`（含**显式 `null`**、**显式空字符串**——服务端 `omitempty` 不会主动发这两种，出现即属异常数据）都视为不可信，客户端不展示按次这一行（宁可少显示，也不能把秒价当次价展示出去） |

无法解析价格的模型省略 `price`，客户端显示"暂无定价"。

## 客户端展示规则（Opus 复核 P1/P2/P4/P5/P6/P7/P8 修订版，取代原版）

**pricing 顶层校验（P1、P6）**：
- `unit` 显式给出且不是 `"usd_per_1m_tokens"` → 整个 `pricing` 不可信，视同缺省，不显示价格区；`unit` 缺省视为默认兼容，仍按 token 类单位处理。
- 只有 `cny_rate` 与 `effective_multiplier` 是必需字段，且必须有限（非 `NaN`/`Infinity`）且严格 `> 0`；任一缺失或无效则整个 `pricing` 不可用。
- `rate_multiplier`/`peak_multiplier` 不再是必需字段，缺失或无效时各自回退到 `1.0`，不影响 `pricing` 整体可用性。
- `peak_active` 显式给出就用显式值；缺省时按未经默认值填充的 `peak_multiplier > 1.0` 推导，`peak_multiplier` 也缺省（或无效）则默认 `false`。

**每模型 price 的字段级校验（P6）**：`input`/`output`/`cache_read`/`cache_write`/`cache_write_1h`/`per_request`/`base_*` 每个字段单独校验，必须有限且 `>= 0`（允许 0，代表免费档位）；负数或非有限（`NaN`/`Infinity`）视为该字段无法解析，单独置空，不影响同一 `price` 对象里的其余字段。

**模型级 `multiplier` 校验（v2）**：必须有限且严格 `> 0`；缺失或无效时置空，客户端回退到顶层 `pricing.effective_multiplier`，不影响 `price` 对象其余字段。

**`per_request_unit` 校验（v3，Codex 验收 C2/C4 修正）**：字段**不存在**时按 `"request"` 处理；显式给出 `"request"`/`"second"` 原样保留；给出其他未识别的值（含**显式空字符串**与**显式 `null`**——这两者都与"字段不存在"是两回事，不能等同处理）时归一化为不可信（客户端内部用 `None`/`null` 表示），不影响 `price` 对象其余字段。

**价格行选择（P2、Q4、Q5、v3）**：
- `billing_mode` 缺省或空字符串按 `"token"` 处理（Q4；客户端在 Rust 侧 `to_price_view` 归一化，前端 `pricing.ts` 再做一次防御性兜底）。
- `billing_mode === "token"` → 展示输入 / 输出 / 缓存读三项（有则显示）；三项全部为空但有 `per_request`（且 `per_request_unit` 可识别）→ 用按次价兜底显示，而不是直接判"暂无定价"。
- `billing_mode !== "token"`（含 `per_request`/`image`/`video` 等契约列出的非 token 计费方式）且有 `per_request` 且 `per_request_unit` 可识别 → 显示按次这一行；没有 `per_request`，或有但 `per_request_unit` 未识别，而有输入/输出/缓存读字段 → 同样兜底展示这些字段（Q5，对称于上一条），而不是直接判"暂无定价"；两条都不满足则"暂无定价"。

**数值展示**：
- 每项同时显示 `¥x.xx / $y.yy`；token 类单位"每百万 tokens"；按次计费单位与行标签按 `per_request_unit` 决定：`"request"` → 标签"按次"/"Per request"、单位"每次"/"Per request"（P8）；`"second"` → 标签"按秒"/"Per second"、单位"每秒"/"Per second"（v3，Opus 复核 R1：标签也要跟着改成"按秒"，不能沿用"按次"标签配"每秒"单位这种自相矛盾的组合）。人民币 = 美元 × `pricing.cny_rate`。
- 数字格式：≥1 保留 2 位小数；<1 且 `>= 0.0001` 保留 4 位有效数字，去掉多余尾零；<1 且 `< 0.0001`（含极小的正数，如 `1e-98`）统一显示 `"<0.0001"`（Codex 验收 C1：继续按有效数字算法会推出超过 `toFixed` 上限的小数位数而抛 `RangeError`，中断整个卡片渲染；即使算出来的位数没超上限，展示几十个前导零对用户也没有意义），不得显示为 `"0"`（会被误读成免费）；非有限值不显示 "0"，显示 "—"（P6，调用方在正常路径下应已过滤，这里只是纯函数自身的防御性兜底）。

**折扣 / 加价展示（P4、P5，v2 改为按模型自己的倍率判定，取代"`effective_multiplier ≠ 1` 时显示划线原价"）**：
- 判定用的倍率 = `price.multiplier ?? pricing.effective_multiplier`（v2：模型自己的倍率优先，媒体类模型不会被顶层因分组高峰而升高的倍率错误影响——v7：会导致独立倍率的所有情形本身都在省略 `price` 的条件列表里，这个场景当前不会出现，是前向兼容保留）。
- 倍率比较使用容差 `|判定倍率 − 1| > 1e-9`（浮点运算可能让"逻辑上等于 1"的倍率出现极小误差）。
- 判定倍率比 1 小超过容差（有折扣）且有对应 `base_*` 原价 → 在折后价旁显示划线原价（`<del>` 元素），但若划线原价与折后价格式化后的文案完全相同（四舍五入巧合）则不显示，避免重复。
- 判定倍率比 1 大超过容差（高峰/加价）→ **不显示划线价**，改在价格区显示"×{倍率} 倍率"标注（倍率数字格式：最多 4 位有效数字、去尾零，如 `1.5`、`2`、`1.004`——Codex 验收 C3：固定 2 位小数会把 `1.004` 四舍五入成 `1.00`、去尾零后变成 `"1"`，和真正倍率为 1 无法区分，必须能保留这类差异）。
- 倍率真正等于 1 时直接显示 `"1"`；不等于 1 但 4 位有效数字仍然格式化成 `"1"`（如 `1.0004`）时逐步升到最多 10 位有效数字，直到结果不再是 `"1"`；即使 10 位仍是 `"1"`（差值贴着 `1e-9` 容差边界）也不能显示 `"1"`，改显示 `"≈1"`（Codex 复验 C5，前缀"≈"，中英通用不需要分别翻译）。
- 判定倍率在容差范围内视为 1 → 既不显示划线价，也不显示倍率标注。
- 划线原价与折后价各自带屏幕阅读器专用（`sr-only`）前缀"原价"/"折后价"（英文 "Original price"/"Discounted price"），不改变可见文案。

**高峰标注（追加需求，取代 Q2 版本"按 `billing_mode === 'token'` 判定"的做法）**：`peak_active=true` **且该模型确实叠加了分组高峰**时才标注"高峰价"；判定不再看 `billing_mode`（普通 `per_request` 计费的模型同样可能叠加分组高峰，仅凭计费方式字符串会误判），改为直接比较数值：`price.multiplier` 缺省，或 `|price.multiplier − pricing.effective_multiplier| ≤ 1e-9`（数值上等于顶层倍率，说明这个模型确实是按顶层倍率计价的）。`multiplier` 独立于分组高峰的模型（数值上不等于顶层 `effective_multiplier`）即使 `peak_active=true` 也不标注——顶层的分组高峰不影响它们的实际计价，标注会误导用户以为这个模型也在涨价（v7：会导致独立倍率的所有情形本身都在省略 `price` 的条件列表里，这条分支当前不会走到，是前向兼容保留）。与"×{倍率} 倍率"标注是两回事，可能同时出现；后者用的是"折扣/加价展示"一节里判定用的倍率（`price.multiplier ?? pricing.effective_multiplier`），不是顶层 `effective_multiplier` 本身。

**页脚（Opus 复核 R2 更新口径说明）**：价格区域下方注明"折后价已含该模型适用的分组倍率与高峰规则；长上下文分档、推理等级等可能使实际扣费不同"；下方另起一行显示这批价格的获取时间（`HH:mm`，本地时区）。

**数据新鲜度（P3，Opus 复核第 2 轮 Q1/Q6 修正）**：价格会随高峰/峰谷边界变化，客户端在下列时机重新拉取当前 Key 的模型与价格（复用既有的模型请求序号保护，静默刷新不打断当前展示内容）：
- 窗口重新可见（`visibilitychange`）或获得焦点（`focus`）时，若距上次拉取已超过 60 秒；
- 页面可见时每 5 分钟定时刷新一次。
- 若这时有一个前台请求（切换 Key、点击"刷新"）仍未完成，静默刷新直接放弃这一次、不抢占请求序号（Q1：否则前台请求 resolve 时序号被静默刷新抢走，`loadingModels` 会永远清不掉，"重试"按钮也跟着一直禁用）；下一次 focus/定时器 tick 再试。
- 静默刷新成功会顺带清掉之前展示的前台错误提示；静默刷新失败只在 console 留痕，但如果失败原因是会话终止类错误（不是单纯的网络抖动）也会通知外壳复查一次会话状态（Q6），不会因为这次刷新"背着用户"发起就把会话失效这件事也悄悄吞掉。

## 已知限制（Opus 第 3 轮复核，用户确认接受；v6/v7 起为纯理论情形）

"高峰标注"一节的判定用数值比较（`price.multiplier` 是否在容差内等于 `pricing.effective_multiplier`）替代 `billing_mode` 判定。如果一个媒体类模型自己独立的倍率**恰好**在数值上等于当前顶层倍率（纯属巧合，与是否真的叠加分组高峰无关），会被误标"高峰价"。服务端没有一个显式字段能区分"这个 `multiplier` 是分组高峰带来的"还是"恰好数值相同的独立倍率"，这是数值判定法固有的边界情况，不打算修复。

**v6 补充说明**：在服务端实际服务范围（B1 只服务 Claude Code/Codex/WorkBuddy 文本工具）下，媒体类模型服务端一律不返回 `price`，也就没有"独立倍率"这个概念——上面这条已知限制目前不会在真实数据里触发，只是给客户端保留的前向兼容能力；如果未来 B1 的服务范围扩展到媒体类模型定价，这条限制才会重新变得有实际意义。

**v7 补充说明**：v7 把"计费模型无法静态确定为模型本身"的所有情形（渠道模型映射、`billing_model_source=response_model`、OpenAI 家族 messages dispatch 映射、账号模型映射、复合分组公开别名显式价、媒体类模型、无价、复合分组公开别名 P 与目标 U 不同且 `billing_model_source=requested`、OpenAI 家族推理后缀归一化结果 ≠ 自身、国产供应商等账号计费候选过滤剔除该模型、无候选账号、原生 messages 请求剥除 `[1m]` 等后缀后归一化结果 ≠ 自身）都收进了省略 `price` 的条件列表，比 v6 单独针对媒体类模型的收窄更彻底：只要服务端返回了 `price`，`multiplier` 就恒等于顶层 `effective_multiplier`，"独立倍率恰好数值相同"这条已知限制不仅在当前范围内不会触发，而且在 v7 的省略条件下**理论上也不再可能触发**（会导致独立倍率的情形本身就会让 `price` 被省略）；这条限制完全降级为对旧版/未升级服务端的前向兼容保留。
